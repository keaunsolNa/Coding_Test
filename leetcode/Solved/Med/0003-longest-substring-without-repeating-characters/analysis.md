## Code Review

**1. 시간 복잡도**  
- **O(N)** (N = 문자열 길이)  
  - `right` 포인터가 문자열을 한 번씩만 순회하고, `left` 포인터도 전체에서 최대 N 번만 이동합니다. 내부 `while` 루프는 중복이 발생했을 때만 실행되며, 각 문자에 대해 `left`가 한 번씩만 증가하므로 전체 연산 횟수는 선형입니다.

**2. 공간 복잡도**  
- **O(1)** (고정 크기 배열)  
  - ASCII 문자 128개에 대한 카운트를 저장하는 `int[128]` 배열만 사용합니다. 입력 문자열 길이에 관계없이 메모리 사용량은 일정합니다.

**3. 풀이 접근법**  
- **슬라이딩 윈도우 + 해시 테이블(배열)**  
  - `right`가 현재 윈도우의 오른쪽 경계를, `left`가 왼쪽 경계를 나타냅니다.  
  - `arr` 배열은 현재 윈도우에 포함된 각 문자 등장 횟수를 기록해 중복 여부를 O(1)로 판단합니다.  
  - 중복이 발견되면 `left`를 오른쪽으로 이동시켜 윈도우를 축소하고, 중복을 제거합니다.  
  - 각 단계에서 윈도우 길이를 갱신해 최장 길이를 구합니다.

**4. 잘된 점**  
- **간결하고 명확한 구현**  
  - 불필요한 객체 생성 없이 기본 배열만 사용해 메모리 오버헤드를 최소화했습니다.  
- **정확한 슬라이딩 윈도우 로직**  
  - `while (arr[cur] > 1)` 로 중복을 바로 감지하고, `left` 를 이동시켜 윈도우를 바로 정리합니다.  
- **가독성**  
  - 변수명(`left`, `right`, `max`, `arr`)이 직관적이며, 로직 흐름이 한눈에 들어옵니다.

**5. 개선 사항**  
- **문자 집합 범위 확대**  
  - 현재는 ASCII(128)만 지원합니다. 유니코드(예: 한글, 이모지) 입력을 고려한다면 `int[256]` 혹은 `Map<Character,Integer>` 로 교체하거나, `int[65536]` (UTF‑16) 로 확장할 수 있습니다.  
- **불필요한 `arr[cur]++` 와 `while` 조건**  
  - 현재 구현은 중복이 발생했을 때만 `while`을 실행하므로 충분히 효율적이지만, `arr[cur]` 를 바로 1로 설정하고 `if (arr[cur] == 2)` 로 조건을 바꾸면 약간의 연산 감소가 가능합니다.  
- **코드 스타일**  
  - `int len = s.length();` 대신 `for (int right = 0, len = s.length(); right < len; right++)` 형태로 선언을 한 줄에 모으면 가독성이 더 높아질 수 있습니다.  
- **예외 처리**  
  - 입력이 `null` 일 경우 NPE가 발생합니다. `if (s == null) return 0;` 과 같은 방어 코드를 추가하면 안정성이 향상됩니다.  

전반적으로 시간·공간 효율이 뛰어나며, 슬라이딩 윈도우 패턴을 잘 적용한 깔끔한 풀이입니다. 필요에 따라 문자 집합을 확장하고, 작은 스타일·안전성 개선을 하면 더욱 완성도 높은 코드가 됩니다.
