## Code Review

**1. 시간 복잡도**  
- 전체 복잡도: **O(m + r)**, 여기서 *m*은 `reservedSeats.length` (예약된 좌석 개수), *r*은 실제로 해시맵에 저장된 행(row) 수(≤ m).  
- 이유:  
  - `for (int[] seat : reservedSeats)` 루프에서 각 예약을 한 번씩 처리해 `HashMap`에 삽입 → O(m).  
  - 각 행마다 좌석 집합을 순회하면서 3개의 구간을 검사 → 각 행에 대해 좌석 수만큼(해당 행에 예약된 좌석 수) 수행, 전체는 다시 m 번.  
  - 그 외 연산은 상수 시간. 따라서 전체는 O(m)이며, n(행 전체 수)은 직접 순회하지 않으므로 O(n)와는 무관합니다.

**2. 공간 복잡도**  
- **O(r + k)**, 여기서 *r*은 해시맵에 저장된 행 수, *k*는 각 행에 저장된 좌석 번호 집합의 크기(전체는 m).  
- `Map<Integer, Set<Integer>>`에 모든 예약 정보를 저장하므로 최악 경우 O(m) 공간을 사용합니다.  
- 추가적인 상수 공간(`ans`, `left/right/middle` 등)만 사용합니다.

**3. 풀이 접근법**  
- **그리디 + 해시맵** 방식:  
  - 행마다 좌석을 3개의 가능한 구간(2~5, 4~7, 6~9)으로 나누어, 해당 구간에 예약이 없으면 가족 한 팀을 배치할 수 있다고 판단합니다.  
  - 한 행에 두 구간(좌·우)이 모두 비어 있으면 2팀, 하나라도 비어 있으면 1팀을 추가합니다.  
- **비트 마스킹** 대신 `Set`을 이용해 구간 포함 여부를 검사하는 단순 구현을 선택했습니다.

**4. 잘된 점**  
- **가독성**: 변수명(`left`, `right`, `middle`)과 주석이 명확해 로직을 바로 이해할 수 있습니다.  
- **불필요한 행 순회 회피**: 전체 행 `n`을 모두 탐색하지 않고, 예약이 있는 행만 처리해 효율성을 높였습니다.  
- **`computeIfAbsent`** 활용으로 코드가 간결하고 `HashMap` 삽입 로직이 깔끔합니다.  

**5. 개선 사항**  
1. **비트 마스크 활용**  
   - 각 행을 10비트(1~10 좌석) 정수로 표현하면 `int mask` 하나만 저장해도 충분합니다.  
   - 구간 검사도 `(mask & LEFT_MASK) == 0` 형태로 O(1) 연산이 가능해, `Set<Integer>` 대신 `int` 하나로 메모리와 시간 모두 절감할 수 있습니다.  

2. **중복 검사 최소화**  
   - 현재는 한 좌석이 동시에 2~5, 4~7, 6~9 구간에 속할 경우 3번 검사됩니다.  
   - 비트 마스크를 쓰면 한 번의 AND 연산으로 3구간 모두 판단할 수 있어 더 깔끔합니다.  

3. **`reserved` 맵의 타입**  
   - `Map<Integer, Set<Integer>>` 대신 `Map<Integer, Integer>`(mask) 로 교체하면, `HashSet` 객체 생성 비용과 내부 오버헤드를 없앨 수 있습니다.  

4. **코드 간소화**  
   - `if (left && right) ans += 2; else if (left || right || middle) ans += 1;` 부분을  
     ```java
     int add = left ? 1 : 0;
     add += right ? 1 : 0;
     if (!left && !right && middle) add = 1;
     ans += add;
     ```  
     와 같이 조금 더 직관적으로 바꿀 수 있지만, 현재 형태도 충분히 명료합니다.  

5. **예외 상황 처리**  
   - 입력이 비어 있거나 `n`이 0인 경우도 정상 동작하지만, 명시적인 체크를 추가하면 가독성이 향상됩니다.  

**요약**  
현재 구현은 가독성이 좋고, 예약이 있는 행만 처리해 효율적이며, `HashMap`·`HashSet`을 이용한 직관적인 접근법을 사용했습니다. 다만, 비트 마스크를 활용하면 메모리 사용량을 O(m) → O(r) (각 행당 1개의 정수) 로 줄이고, 구간 검사를 상수 시간에 수행할 수 있어 더욱 최적화된 해결책이 됩니다.
