## Code Review

**코드 리뷰**

1. **시간 복잡도**: O(n^2) - 현재 구현된 코드는 두 개의 중첩된 반복문을 사용하여 리스트의 원소를 처리합니다. 리스트의 크기가 n일 때, 각 원소에 대해 리스트를 다시 반복하기 때문에 시간 복잡도가 O(n^2)입니다.

2. **공간 복잡도**: O(n) - 입력 문자열을 리스트로 변환하여 처리하므로, 리스트의 크기는 입력 문자열의 크기와 동일합니다. 따라서 공간 복잡도는 O(n)입니다.

3. **풀이 접근법**: Greedy 알고리즘을 사용하여 각 원소에 대해 즉시 처리합니다. 하지만, 현재 구현된 코드는 리스트의 원소를 반복적으로 제거하면서 인덱스를 사용하여 접근하므로, 효율적인 처리가 아닙니다. 큐(Queue) 자료구조를 사용하여 각 원소의 순서를 유지하면서 처리하는 방식이 더 적절할 수 있습니다.

4. **잘된 점**: 코드는 문제의 요구사항을 이해하고, 기본적인 로직을 구현했습니다. 또한, 코드의 구조는 비교적 단순하고 이해하기 쉽습니다.

5. **개선 사항**: 
- 리스트에서 원소를 제거하는 과정에서 인덱스 처리가 복잡합니다. 큐를 사용하여 순서를 유지하면서 처리하는 방식으로 변경할 수 있습니다.
- 반복문이 중첩되어 있어 시간 복잡도가 높습니다. 큐를 사용하여 처리하면, 각 원소에 대해 한 번씩만 처리하므로 시간 복잡도를 개선할 수 있습니다.
- while문 조건이 `list.size() == 1`로 설정되어 있습니다. 하지만, 이 조건은 리스트에 원소가 하나만 남았을 때만 참이 됩니다. 따라서, 리스트에서 원소가 하나만 남았을 때를 체크하는 별도의 조건문을 추가할 필요가 있습니다.
