## Code Review

**1. 시간 복잡도**  
- **O(n)** : `colors` 배열을 한 번 순회하면서 인접 원소를 비교합니다. `n` 은 배열 길이이며, 루프와 양 끝에 수행되는 상수 시간 연산만 존재하므로 선형 시간 복잡도입니다.

**2. 공간 복잡도**  
- **O(1)** : 추가적인 배열이나 리스트를 사용하지 않고, 몇 개의 정수 변수(`ans`, `len`, `i`)만 선언합니다. 따라서 입력 크기에 비례하는 메모리를 사용하지 않습니다.

**3. 풀이 접근법**  
- **슬라이딩 윈도우(고정 길이 3)** 형태로 인접 3개의 원소를 확인합니다.  
- 각 위치 `i`(1 ≤ i ≤ n‑2)에서 `colors[i]` 가 양옆 원소와 모두 다르면 교대 그룹의 시작점으로 간주하고 카운트합니다.  
- 원형 배열이므로 첫 번째와 마지막 원소에 대해서도 별도로 검사합니다.

**4. 잘된 점**  
- **단순하고 직관적인 구현** : 인접 원소만 비교하면 되므로 복잡한 로직 없이 문제를 해결했습니다.  
- **불필요한 자료구조 사용 금지** : 메모리를 절약하면서 O(1) 공간을 유지했습니다.  
- **경계 조건 처리** : 원형 배열 특성을 고려해 첫 번째와 마지막 원소를 별도 체크한 점이 정확합니다.

**5. 개선 사항**  
1. **루프 범위와 경계 처리 통합**  
   - 현재는 `for` 루프와 별도의 두 번의 `if` 문으로 첫·마지막 원소를 처리하고 있어 코드가 중복됩니다.  
   - 배열을 두 번 순회하거나, 배열을 `colors` 뒤에 `colors[0]` 과 `colors[1]` 을 추가한 **확장 배열**(예: `int[] ext = new int[n+2];`) 로 만든 뒤 일반적인 `for (int i = 1; i < n+1; i++)` 로 처리하면 경계 검사를 하나의 루프에 통합할 수 있습니다.

2. **가독성 향상**  
   - 조건식을 메서드(`isAlternating(i)`) 혹은 의미 있는 변수(`prev = colors[i-1]; cur = colors[i]; next = colors[i+1];`) 로 분리하면 읽기 쉬워집니다.  
   - 현재 `if (colors[i] != colors[i - 1] && colors[i] != colors[i + 1]) ans++;` 와 같이 한 줄에 두 조건이 섞여 있어, 논리 흐름을 파악하기 다소 어려울 수 있습니다.

3. **예외 상황 처리**  
   - `colors.length` 가 1인 경우 현재 구현은 `colors[1]` 에 접근해 `ArrayIndexOutOfBoundsException` 을 발생시킵니다. 문제 제약에 따라 최소 길이가 2 이상일 수도 있지만, 안전하게 `if (len < 2) return 0;` 과 같은 방어 코드를 추가하는 것이 좋습니다.

4. **대안 알고리즘** (선택 사항)  
   - **연속 구간 길이 카운팅**: 연속으로 교대되는 구간의 길이를 구하고, 길이가 `k` 이상이면 `k-2` 개의 시작점을 더하는 방식으로도 해결할 수 있습니다. 이 방법은 `k` 가 3인 경우와 동일하지만, 일반화된 형태(예: `k` 가 변할 때)에도 확장성이 좋습니다.
