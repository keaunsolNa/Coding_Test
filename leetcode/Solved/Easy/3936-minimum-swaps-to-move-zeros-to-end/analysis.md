## Code Review

**1. 시간 복잡도**  
- **O(n)**  
  - `i`와 `j`가 각각 배열을 한 번씩만 순회합니다. 내부 `while` 루프도 전체적으로는 각 인덱스를 최대 한 번씩만 방문하므로 전체 연산 횟수는 배열 길이 `n`에 비례합니다.

**2. 공간 복잡도**  
- **O(1)**  
  - 추가로 사용하는 변수는 `ans`, `n`, `i`, `j` 네 개뿐이며, 입력 배열을 그대로 사용합니다. 따라서 입력 크기에 비례하는 메모리를 할당하지 않습니다.

**3. 풀이 접근법**  
- **양쪽 포인터(two‑pointer) 기법**을 이용해 왼쪽에서 0을 찾고, 오른쪽에서 0이 아닌 값을 찾은 뒤 교환이 필요함을 카운트합니다. 실제 교환을 수행하지는 않으며, 교환이 필요한 쌍의 개수만 세어 최소 스왑 횟수를 구합니다.

**4. 잘된 점**  
- **불필요한 배열 복사나 추가 자료구조 없이** O(1) 공간으로 문제를 해결했습니다.  
- `i`와 `j`를 동시에 증가·감소시키는 구조가 깔끔하고, `if (i >= j) break;` 로 종료 조건을 명확히 했습니다.  
- `ans`만 증가시키고 실제 배열을 바꾸지 않아 코드가 간결합니다.

**5. 개선 사항**  
1. **루프 변수 증가 방식**  
   - 현재 `for (int i = 0, j = n - 1; i < j; ++i, --j)` 로 `i`와 `j`를 매 반복마다 무조건 이동시키고 있습니다. 하지만 `while` 내부에서 이미 `i`와 `j`를 여러 번 건너뛰기 때문에 `for` 문에서 `++i, --j`는 불필요한 추가 이동을 일으킬 수 있습니다.  
   - **수정 예시**  
     ```java
     int i = 0, j = n - 1;
     while (i < j) {
         while (i < n && nums[i] != 0) i++;
         while (j >= 0 && nums[j] == 0) j--;
         if (i >= j) break;
         ans++;
         i++;
         j--;
     }
     ```
2. **경계 조건**  
   - `while (j > 0 && nums[j] == 0)` 은 `j >= 0` 로 바꾸는 것이 안전합니다. 현재 `j`가 0일 때 `nums[0]`이 0이면 루프를 빠져나오지 못하고 `j`가 -1이 될 위험이 있습니다(실제 동작은 `i < j` 조건에 의해 멈추지만, 가독성을 위해 명확히 하는 것이 좋습니다).  
3. **불필요한 `n` 변수**  
   - `n`은 `nums.length`와 동일하므로, 직접 `nums.length`를 사용해도 무방합니다. 코드 가독성을 위해 `int n = nums.length;` 를 유지해도 좋지만, 메모리 절약 차원에서는 의미가 없습니다.  
4. **알고리즘 설명 주석 추가**  
   - 왜 `ans`가 최소 스왑 횟수가 되는지, 0과 0이 아닌 원소를 교환하는 것이 최적임을 간단히 주석으로 남기면 가독성이 향상됩니다.

**요약**  
현재 구현은 시간·공간 모두 최적에 가깝지만, `for` 문에서 포인터를 동시에 이동시키는 부분을 `while` 루프로 정리하고 경계 조건을 명확히 하면 더 안전하고 가독성 높은 코드가 됩니다. 전체적인 로직은 매우 적절하며, 두 포인터 기법을 잘 활용한 좋은 풀이입니다.
