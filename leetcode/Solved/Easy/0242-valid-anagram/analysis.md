## Code Review

**1. 시간 복잡도**  
- 현재 구현은 두 문자열을 각각 한 번씩 순회하고(`O(n + m)`), 이후에 두 `Map`의 키 집합을 각각 순회합니다. 키 집합의 크기는 알파벳 종류(최대 26·또는 전체 유니코드)이므로 최악의 경우에도 `O(k)`이며, `k ≤ n + m` 로 볼 수 있습니다. 따라서 전체 시간 복잡도는 **O(n + m)** (보통 `n = m` 로 가정하면 **O(n)**) 입니다.

**2. 공간 복잡도**  
- 두 개의 `HashMap<Character, Integer>` 를 사용해 각각 문자열에 등장하는 문자와 개수를 저장합니다. 최악의 경우 모든 문자가 서로 다르면 `Map` 의 크기는 문자열 길이와 동일합니다. 따라서 **O(n + m)** 의 추가 공간이 필요합니다. (알파벳만 사용한다면 실제 메모리는 `O(1)` 로도 볼 수 있습니다.)

**3. 풀이 접근법**  
- **해시 테이블**을 이용해 각 문자열의 문자 빈도를 카운트한 뒤, 두 해시 테이블을 비교하는 방식입니다.  
- `Map.getOrDefault` 로 카운트를 증가시키고, 이후 `keySet()` 을 순회하면서 값이 일치하는지 검사합니다.

**4. 잘된 점**  
- `getOrDefault` 를 활용해 카운팅 로직을 간결하게 구현한 점이 좋습니다.  
- 두 문자열을 각각 별도의 `Map`에 저장해 비교 로직을 명확히 분리한 점이 가독성을 높입니다.  
- 디버깅용 `System.out.println` 을 넣어 중간 상태를 확인하려는 시도는 테스트 단계에서 유용합니다.

**5. 개선 사항**  
1. **불필요한 두 번째 Map 제거**  
   - 두 문자열을 동시에 한 번의 `Map`에 카운트하고, 두 번째 문자열을 순회하면서 차감하면 하나의 `Map`만으로 충분합니다. 이렇게 하면 비교 루프가 하나로 줄어들고, 코드가 더 간결해집니다.  
   - 예시)  
     ```java
     int[] cnt = new int[26]; // 알파벳만 사용한다면 배열 사용 권장
     for (char c : s.toCharArray()) cnt[c - 'a']++;
     for (char c : t.toCharArray()) {
         if (--cnt[c - 'a'] < 0) return false;
     }
     return true;
     ```
2. **불필요한 `null` 체크 간소화**  
   - 현재 `if (null != tMap.get(key) && tMap.get(key) != sMap.get(key))` 와 같은 코드는 `tMap.getOrDefault(key, 0) != sMap.get(key)` 로 한 줄로 표현할 수 있습니다.  
   - 또한 두 번째 `for` 루프는 첫 번째 루프에서 이미 모든 키를 검사했으므로 중복됩니다. 하나의 루프만으로 충분합니다.
3. **디버깅 출력 제거**  
   - 실제 제출 코드에서는 `System.out.println` 이 불필요하며, I/O 비용을 증가시킬 수 있으니 제거합니다.
4. **문자 집합이 제한되지 않은 경우**  
   - 알파벳 외의 모든 유니코드 문자를 지원하려면 `int[256]` 혹은 `Map<Character, Integer>` 를 그대로 사용하되, 위에서 제시한 차감 방식으로 구현하면 여전히 **O(n)** 시간, **O(k)** (k는 서로 다른 문자 수) 공간을 유지합니다.

**요약**  
현재 코드는 올바르게 동작하지만, 두 개의 `Map`과 두 번의 키 순회를 사용해 불필요한 복잡도가 존재합니다. 하나의 해시 테이블(또는 고정 크기 배열)로 카운트를 수행하고 차감하는 방식으로 바꾸면 **시간·공간 모두 최적화**된 간결한 구현이 됩니다.
