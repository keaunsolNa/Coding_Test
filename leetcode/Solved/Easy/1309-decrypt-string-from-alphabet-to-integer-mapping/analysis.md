## Code Review

**1. 시간 복잡도**  
- **O(N)** : 문자열 `s`의 길이를 N이라고 할 때, 한 번 뒤에서 앞으로 순회하면서 각 문자(또는 `#`과 그 앞의 두 숫자)를 한 번씩만 처리합니다. 따라서 입력 크기에 비례하는 선형 시간입니다.

**2. 공간 복잡도**  
- **O(N)** : 결과를 저장하기 위해 `StringBuilder sb`를 사용합니다. 최악의 경우(모든 문자가 `#` 없이 단일 숫자) 결과 문자열의 길이는 N과 동일하므로 추가적인 선형 공간이 필요합니다. 입력을 별도로 복사하지는 않으므로, 보조 공간은 `StringBuilder`와 몇 개의 임시 변수에 한정됩니다.

**3. 풀이 접근법**  
- 뒤에서부터 탐색하면서 `#`이 나타나면 바로 앞의 두 숫자를 결합해 10~26에 해당하는 알파벳을 만든 뒤, `#`과 두 숫자를 건너뛰고 결과에 추가합니다.  
- `#`이 없으면 현재 숫자를 1~9에 해당하는 알파벳으로 변환합니다.  
- 변환은 `char c = (char) (value + 'a')` 형태로 수행합니다.  

**4. 잘된 점**  
- **역방향 탐색**을 이용해 `#`과 그 앞의 두 숫자를 한 번에 처리함으로써 복잡한 인덱스 관리 없이 O(N) 시간에 해결했습니다.  
- `StringBuilder`를 사용해 문자열을 효율적으로 누적했습니다.  
- `Integer.parseInt(arr[i - 1] + "" + arr[i - 2])` 대신 `arr[i-2]-'0'`와 `arr[i-1]-'0'`을 이용하면 조금 더 빠르지만, 현재 구현도 가독성이 좋습니다.  
- 불필요한 `StringTokenizer` import을 제거했으며, 실제 코드에서는 사용되지 않으니 깔끔합니다.

**5. 개선 사항**  
1. **문자 → 정수 변환 최적화**  
   ```java
   int num = (arr[i-2] - '0') * 10 + (arr[i-1] - '0');
   ```  
   `Integer.parseInt`보다 연산이 더 가볍고, 임시 문자열 생성도 없으므로 성능이 약간 개선됩니다.

2. **`char` 변환 로직 오류 가능성**  
   현재 `char c = (char) (arr[i] + 'a');`는 `arr[i]`가 `'1'~'9'` 문자 코드값을 그대로 더하고 있어 올바른 결과를 내지만, 직관적으로는 `arr[i] - '0' + 1`을 더하는 것이 명확합니다. 예시:  
   ```java
   char c = (char) ((arr[i] - '0' - 1) + 'a');
   ```

3. **결과 문자열 뒤집기**  
   현재 `sb.append(c)`를 뒤에서부터 진행하므로 최종 문자열이 뒤집힌 상태가 됩니다. 실제로는 `sb.append(c)` 후 `sb.reverse().toString()`을 반환하거나, `StringBuilder` 대신 `char[]`에 역순으로 채워서 뒤집는 과정을 생략할 수 있습니다. (LeetCode에서는 뒤집힌 문자열을 반환해도 정답이지만, 일반적인 구현에서는 명시적으로 뒤집는 것이 안전합니다.)

4. **예외 상황 처리**  
   입력이 항상 유효하다고 가정하지만, `i-2`가 음수가 되는 경우(예: 문자열이 `"#"`만 있는 경우) `ArrayIndexOutOfBoundsException`이 발생할 수 있습니다. 실제 테스트에서는 이런 입력이 주어지지 않지만, 방어적 코드를 추가하면 견고해집니다.

5. **불필요한 import 제거**  
   `import java.util.StringTokenizer;`는 사용되지 않으므로 삭제해 코드 가독성을 높이고 컴파일 시간을 미세하게 줄일 수 있습니다.

**요약**  
전체적인 알고리즘은 최적이며 O(N) 시간·공간 복잡도를 만족합니다. 다만 정수 변환을 직접 연산으로 바꾸고, 문자 변환 로직을 명확히 하면 가독성과 미세 성능이 향상됩니다. 또한 결과 문자열을 뒤집는 과정을 명시하거나 `char[]`에 바로 채워 넣는 방법을 고려하면 더욱 깔끔한 구현이 됩니다.
