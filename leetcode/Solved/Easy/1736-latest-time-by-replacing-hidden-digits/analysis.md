## Code Review

**1. 시간 복잡도**  
- **O(1)**  
  입력 문자열의 길이는 항상 고정된 5(`HH:MM`)이며, `split`, `charAt`, 문자열 연결 등 수행되는 연산이 상수 개수이므로 전체 실행 시간은 입력 크기에 독립적이다.

**2. 공간 복잡도**  
- **O(1)**  
  추가로 생성되는 문자열은 `hour`, `min`, 그리고 최종 반환 문자열 정도뿐이며, 모두 길이가 고정돼 있다. 따라서 사용되는 메모리도 입력 크기에 비례하지 않는다.

**3. 풀이 접근법**  
- **그리디** 방식으로 각 자리(`?`)에 가능한 가장 큰 숫자를 채워서 가장 늦은 시간을 만든다.  
  - 시(`hour`)의 첫 번째 자리: `?`이면 `2`를 넣는다(24시 형식의 최댓값).  
  - 시의 두 번째 자리: 첫 번째 자리가 `2`이면 `3`(23시), 아니면 `9`(09~19시) 중 큰 값을 넣는다.  
  - 분(`min`)의 첫 번째 자리: `?`이면 `5`(59분), 두 번째 자리: `?`이면 `9`를 넣는다.  

**4. 잘된 점**  
- 문제의 핵심인 “가능한 가장 큰 유효 시간”을 간결하게 구현했다.  
- 불필요한 반복이나 조건 검사를 최소화해 가독성이 좋다.  
- `split(":")` 로 시와 분을 바로 분리해 로직을 직관적으로 구성했다.  

**5. 개선 사항**  

| 항목 | 내용 | 이유 |
|------|------|------|
| **불필요한 `split` 중복** | `String[] parts = time.split(":");` 후 `hour = parts[0]; min = parts[1];` 로 한 번만 분리 | 현재는 `time.split(":")` 를 두 번 호출해 약간의 오버헤드가 발생한다. |
| **문자열 연결 방식** | `hour = hour.charAt(0) + (hour.charAt(0) == '2' ? "3" : "9");` 와 같이 `char + String` 연산은 암묵적으로 `int` 로 변환 후 문자열로 바뀌어 비효율적 | `StringBuilder` 혹은 `char[]` 로 직접 조작하면 더 명확하고 성능이 일정해진다. |
| **유효성 검증 로직** | `if ((char) hour.charAt(1) - '0' >= 4) hour = "1" + hour.charAt(1);` 은 실제로 필요 없는 경우가 있다. 첫 번째 자리가 `2`가 아닌 경우 두 번째 자리는 `0~9` 모두 허용되므로 이 조건은 `hour.charAt(0) == '2'` 와 결합해서 체크하는 것이 안전하고 명확함. | 현재 로직은 첫 번째 자리가 `2`가 아니어도 `hour.charAt(1)` 가 `4~9` 일 때 `1x` 로 바꾸어 잘못된 결과를 만들 수 있다. (예: `"??:??"` → 첫 번째 `?` 를 `2` 로 바꾸고 두 번째 `?` 를 `9` 로 바꾸면 `29` 가 되지만 실제로는 `23`이어야 함) |
| **예외 입력 처리** | 입력이 반드시 `HH:MM` 형식이라고 가정하지만, LeetCode 외부에서 재사용할 경우 `null` 혹은 길이 오류에 대한 방어 코드가 없음 | `if (time == null || time.length() != 5) return "";` 와 같은 방어 코드를 추가하면 견고함이 향상된다. |
| **전체 로직 단순화** | `char[] arr = time.toCharArray();` 로 배열을 만든 뒤 인덱스별로 직접 대입하면 조건문이 4~5줄로 줄어들고 가독성이 높아진다. | 예시: `if (arr[0] == '?') arr[0] = (arr[1] <= '3' ? '2' : '1');` 등 |

**예시 개선 코드 (간결 버전)**  

```java
class Solution {
    public String maximumTime(String time) {
        char[] t = time.toCharArray();   // HH:MM

        // hour tens
        if (t[0] == '?') t[0] = (t[1] != '?' && t[1] > '3') ? '1' : '2';
        // hour units
        if (t[1] == '?') t[1] = (t[0] == '2') ? '3' : '9';
        // minute tens
        if (t[3] == '?') t[3] = '5';
        // minute units
        if (t[4] == '?') t[4] = '9';

        return new String(t);
    }
}
```

이 버전은 `split` 과 문자열 연결을 없애고, 상수 크기의 배열을 직접 수정함으로써 **시간·공간 복잡도는 그대로 O(1)** 이면서 코드가 더 직관적이고 오류 가능성이 낮아진다.
