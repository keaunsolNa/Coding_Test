## Code Review

**1. 시간 복잡도**  
- **O(1)**  
  입력 문자열은 항상 길이가 5(`hh:mm`)인 고정 크기이므로, 문자열을 split하고 각 자리 문자를 검사·대입하는 연산은 상수 횟수만 수행됩니다. 따라서 입력 크기에 비례하는 반복이 없으며 시간 복잡도는 O(1)입니다.

**2. 공간 복잡도**  
- **O(1)**  
  추가로 생성되는 문자열은 `hour`, `min`, 그리고 최종 반환 문자열 하나뿐이며, 모두 길이가 고정되어 있습니다. 따라서 사용되는 메모리는 입력 크기에 독립적인 상수 공간입니다.

**3. 풀이 접근법**  
- **그리디(Greedy) 방식**  
  각 자리(`?`)에 가능한 가장 큰 숫자를 채워 넣어 전체 시간을 최대화합니다.  
  - 시(`hour`)의 첫 자리: 가능한 최대값은 `2` (24시 형식) → 첫 자리가 `?`이면 `2`로 채움.  
  - 시의 두 번째 자리: 첫 자리가 `2`이면 `3`(23시까지), 아니면 `9`(09~19시)로 채움.  
  - 분(`min`)의 첫 자리: `5`(00~59분)로, 두 번째 자리: `9`로 채워 최대 분을 만든다.  

**4. 잘된 점**  
- **문제 요구사항을 정확히 반영**: 24시간 형식과 분 범위를 고려해 각각의 자리마다 가능한 최댓값을 올바르게 선택하고 있습니다.  
- **코드가 간결**: 불필요한 반복이나 복잡한 로직 없이 몇 줄의 조건문만으로 해결하고 있어 가독성이 좋습니다.  
- **불필요한 객체 생성 최소화**: `split(":")` 한 번만 사용하고, 문자열 재조합도 최소한으로 수행합니다.

**5. 개선 사항**  
1. **`split` 호출 중복 제거**  
   ```java
   String[] parts = time.split(":");
   String hour = parts[0];
   String min  = parts[1];
   ```
   현재는 `time.split(":")`를 두 번 호출하고 있어 약간의 오버헤드가 발생합니다. 한 번만 호출하도록 수정하면 더 깔끔합니다.

2. **문자와 문자열 결합 방식 통일**  
   현재 `hour = hour.charAt(0) + (hour.charAt(0) == '2' ? "3" : "9");` 와 같이 `char + String` 형태가 혼재되어 있습니다. `StringBuilder` 혹은 `String.format`을 사용하면 타입 혼동을 피할 수 있습니다.

3. **조건 로직 간소화**  
   `chk` 플래그와 `if ((char) hour.charAt(1) - '0' >= 4 && chk)` 부분은 다음과 같이 한 번에 처리할 수 있습니다.
   ```java
   if (hour.charAt(0) == '?') {
       hour = (hour.charAt(1) <= '3') ? "2" + hour.charAt(1) : "1" + hour.charAt(1);
   } else if (hour.charAt(1) == '?') {
       hour = hour.charAt(0) + (hour.charAt(0) == '2' ? "3" : "9");
   }
   ```
   이렇게 하면 `chk` 변수를 없앨 수 있어 코드가 더 직관적입니다.

4. **예외 상황 처리**  
   현재 구현은 입력이 항상 `hh:mm` 형식이라고 가정합니다. LeetCode에서는 보장이 되지만, 실제 서비스 코드라면 입력 검증(길이, `:` 위치 등)을 추가하는 것이 안전합니다.

5. **테스트 커버리지**  
   경계값(`??:??`, `2?:?9`, `0?:?0` 등)과 일반 케이스를 모두 포함한 단위 테스트를 작성하면 리팩터링 후에도 동작을 보장할 수 있습니다.
