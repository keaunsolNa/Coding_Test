## Code Review

**1. 시간 복잡도**  
- 현재 구현은 각 행마다 `Arrays.sort(arr)` 를 수행하므로 행당 `O(m log m)` (m = 열의 개수) 시간이 듭니다. 전체 행 수를 n이라 하면 전체 시간 복잡도는 **O(n·m log m)** 입니다.  
- 정렬 후에 음수를 세는 루프는 최악의 경우 `O(m)` 이지만 정렬 비용이 지배적이므로 무시됩니다.

**2. 공간 복잡도**  
- `Arrays.sort` 는 입력 배열을 제자리(in‑place) 정렬하므로 추가적인 힙 메모리는 거의 사용하지 않습니다. 따라서 **O(1)** (입력 외 추가 공간) 입니다. 다만 정렬 구현에 따라 스택 깊이가 `O(log m)` 정도 필요할 수 있습니다.

**3. 풀이 접근법**  
- 각 행을 오름차순으로 정렬한 뒤, 앞쪽(음수 쪽)부터 순회하면서 0 이상이 나오면 멈추고 음수 개수를 누적합니다.  
- 기본적인 **정렬 + 선형 탐색** 방식이며, 문제에서 요구하는 “정렬된 행”이라는 전제를 활용하지 못하고 있습니다.

**4. 잘된 점**  
- 코드가 간결하고 가독성이 좋습니다.  
- `for‑each` 문을 사용해 행을 순회하고, `break` 로 불필요한 탐색을 중단하는 로직이 명확합니다.  
- 별도의 자료구조를 만들지 않아 메모리 사용이 최소화되었습니다.

**5. 개선 사항**  
1. **정렬된 행 활용**  
   - 입력 `grid` 의 각 행은 이미 **오름차순**(또는 내림차순)으로 정렬돼 있습니다. 따라서 다시 정렬할 필요가 없습니다. 정렬을 제거하면 시간 복잡도를 `O(n·m)` 로 줄일 수 있습니다.  

2. **이진 탐색 활용**  
   - 각 행이 오름차순이라면, 첫 번째 음수가 나타나는 인덱스를 이진 탐색(`Arrays.binarySearch` 혹은 직접 구현)으로 찾을 수 있습니다. 이 경우 한 행당 `O(log m)` 시간, 전체 `O(n·log m)` 로 더 효율적입니다.  

3. **두 포인터(스텝) 방식**  
   - 행은 오름차순, 열도 오름차순이므로 오른쪽 위(0, m‑1)에서 시작해 아래로 이동하거나 왼쪽으로 이동하는 **O(n+m)** 알고리즘이 가능합니다.  
   - 예시: `row = 0, col = m‑1; while(row < n && col >= 0){ if(grid[row][col] < 0){ cnt += col+1; row++; } else { col--; } }`  

4. **불필요한 정렬 제거**  
   - 현재 `Arrays.sort(arr);` 라인은 문제 요구사항에 어긋나며, 원본 데이터를 변형시킬 위험이 있습니다. 정렬을 제거하고 원본 배열을 그대로 사용하세요.  

5. **예외 상황 처리**  
   - 입력이 `null` 이거나 빈 배열일 경우를 대비한 방어 코드가 있으면 더욱 견고합니다.  

**요약**  
현재 코드는 정렬을 불필요하게 수행해 `O(n·m log m)` 의 시간 복잡도를 갖습니다. 행이 이미 정렬돼 있다는 점을 활용하면 `O(n·m)` 혹은 `O(n·log m)` (이진 탐색) 혹은 `O(n+m)` (두 포인터) 로 최적화할 수 있습니다. 정렬을 제거하고, 이진 탐색이나 스텝 방식으로 구현한다면 더 효율적인 풀이가 됩니다.
