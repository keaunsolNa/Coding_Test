**코드 리뷰**

| 구분 | 내용 |
|------|------|
| **시간 복잡도** | `O(R·C)`<br>여기서 `R`은 범위에 포함된 열(알파벳) 개수(`twoC - oneC + 1`), `C`는 행(숫자) 개수(`twoNum - oneNum + 1`)이다. 두 중첩 `for` 루프가 각각 모든 열·행을 한 번씩 방문하므로 전체 셀 개수만큼 연산이 수행된다. 입력 길이는 고정(5자리)이라서 최악의 경우(`A1:Z9`)에도 `26·9 = 234`번의 반복만 수행한다. |
| **공간 복잡도** | `O(R·C)`<br>결과 리스트에 모든 셀 문자열을 저장해야 하므로 반환 리스트의 크기와 동일한 메모리를 사용한다. 추가적인 보조 공간은 `O(1)`이다. |
| **풀이 접근법** | 문자열을 `":"` 로 split하여 시작 셀과 끝 셀을 구하고, 각각의 열 문자와 행 숫자를 추출한다. 열 문자(`char`)와 행 숫자(`int`)를 이용해 두 중첩 `for` 루프를 돌면서 `c + "" + i` 형태로 셀 주소를 만든 뒤 리스트에 추가한다. 이는 **직접 시뮬레이션** 방식이며, 범위에 포함된 모든 셀을 순차적으로 생성한다. |
| **잘된 점** | - `split(":")` 로 시작·끝을 명확히 구분해 가독성이 좋다.<br>- `char` 를 그대로 증감하면서 열을 순회해 알파벳 순서를 정확히 유지한다.<br>- `ArrayList` 를 사용해 동적 배열을 활용, 반환 타입(`List<String>`)과 일치한다.<br>- 코드가 짧고 직관적이라 이해하기 쉽다. |
| **개선 사항** | 1. **불필요한 `split` 호출 최소화**<br>```java<br>String[] parts = s.split(\":\");<br>String one = parts[0];<br>String two = parts[1];<br>```<br>현재는 `s.split(":")` 를 두 번 호출해 동일한 배열을 두 번 생성한다. 한 번만 호출하면 메모리와 약간의 시간 비용을 절감할 수 있다.<br><br>2. **행 숫자 파싱 간소화**<br>`int oneNum = one.charAt(1) - '0';` 로 충분하고 `int` 형 변환은 필요 없다.<br><br>3. **문자열 결합 방식 개선**<br>`c + "" + i` 대신 `StringBuilder` 를 사용하거나 `c + String.valueOf(i)` 로도 충분하지만, 현재 규모에서는 큰 차이가 없으니 가독성을 위해 그대로 두어도 무방하다.<br><br>4. **입력 검증** (선택 사항)<br>문제에서는 입력이 항상 유효하다고 가정하지만, 실제 서비스 코드라면 `s.length() == 5 && s.charAt(2) == ':'` 등 기본 검증을 추가하면 안전하다.<br><br>5. **메서드 분리** (가독성 향상)<br>열·행 파싱 로직을 별도 메서드로 추출하면 테스트와 재사용이 용이해진다. 예: `private int parseRow(String cell)` 등. |
