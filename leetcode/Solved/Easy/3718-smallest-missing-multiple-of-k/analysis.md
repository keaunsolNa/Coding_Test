## Code Review

**코드 리뷰**

---

### 1. 시간 복잡도  
- **전체 복잡도: O(N + M/k)**  
  - `for (int i : nums) arr[i] = true;` : 배열 `nums` 를 한 번 순회 → **O(N)** (N = `nums.length`).  
  - `while` 루프 : `ans` 를 `k`씩 증가시키면서 존재 여부를 검사. 최악의 경우 `ans` 가 `max(nums)` 를 초과할 때까지 진행하므로 약 `max(nums)/k` 번 반복 → **O(M/k)** (M = `max(nums)`).  
  - 따라서 전체는 `O(N + M/k)`. 입력값이 10⁵ 이하라면 충분히 빠릅니다.

### 2. 공간 복잡도  
- **O(100000)** (고정된 크기의 `boolean[] arr`).  
  - 문제에서 `nums` 의 값이 0~10⁵ 이하라고 가정했을 때, 이 배열은 최대 100 000개의 불리언을 차지합니다.  
  - 입력 크기에 비례하지 않는 **상수 공간**이라고 볼 수 있지만, 실제 제한이 더 크면 메모리 초과 위험이 있습니다.

### 3. 풀이 접근법  
- **해시 테이블(인덱스 기반) 방식**: `boolean[]` 를 이용해 존재 여부를 O(1) 로 확인하고, `k`의 배수를 차례대로 검사하면서 가장 작은 누락된 배수를 찾는다.  
- **그리디 탐색**: 현재 후보 `ans` 가 배열에 있으면 `k` 를 더하고, 없으면 바로 정답으로 반환한다.

### 4. 잘된 점  
- **O(1) 존재 검사**를 위해 인덱스 기반 `boolean` 배열을 사용한 점이 효율적이다.  
- 로직이 직관적이며, `while(true)` 안에서 바로 `break` 로 종료해 가독성이 좋다.  
- `ans` 를 `k` 단위로 증가시키는 그리디 방식이 문제 요구사항에 정확히 부합한다.

### 5. 개선 사항  
1. **배열 크기 동적화**  
   - 현재 `boolean[100000]` 은 하드코딩되어 있다. `nums` 에서 최대값을 미리 구하고 `max+1` 크기의 배열을 할당하면 메모리를 절약할 수 있다.  
   - 혹은 `HashSet<Integer>` 를 사용하면 값의 범위가 제한되지 않아 더 일반적인 풀이가 된다 (시간 복잡도는 O(1) 평균).

2. **불필요한 출력 제거**  
   - `System.out.print(ans + " ");` 는 디버깅용이라면 제거하거나 주석 처리한다. 실제 제출 시에는 I/O 비용이 불필요하게 추가된다.

3. **경계 조건 처리**  
   - `nums` 에 0 이 포함될 경우 `arr[0]` 에 접근하게 되는데, 문제에서 0 이 허용되지 않을 경우 명시적으로 체크하거나 `boolean` 배열을 `size = max+1` 로 잡아야 한다.

4. **루프 종료 조건 명시**  
   - `while (true)` 보다는 `while (arr[ans]) { ans += k; }` 와 같이 조건을 명시하면 가독성이 향상된다.

5. **시간 복잡도 최적화 (대안)**  
   - `k` 가 1인 경우 모든 정수를 순차 탐색하게 되므로 최악 O(M) 가 된다. 이때는 `HashSet` 에 모든 `nums` 를 넣고 `for (int i = k; ; i += k)` 로 바로 탐색하는 것이 메모리와 시간 모두 비슷하지만 구현이 간결하다.

현재 구현은 제한된 입력 범위 내에서는 충분히 빠르고 메모리도 적절히 사용한다. 다만 배열 크기를 하드코딩한 점과 디버깅 출력이 남아 있는 점을 보완하면 더욱 견고하고 범용적인 코드가 된다.
