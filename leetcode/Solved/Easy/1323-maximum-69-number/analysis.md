### 1. 시간 복잡도  
- **O(n)** (n : 입력 정수 `num`을 10진수 문자열로 변환했을 때의 자리수)  
- 문자열을 한 번 순회하면서 첫 번째 `'6'`을 찾고, 그 뒤에 바로 `break` 하므로 최악의 경우에도 전체 자리수를 한 번씩만 확인한다.  

### 2. 공간 복잡도  
- **O(n)**  
- `num + ""` 로 만든 문자열과 `toCharArray()` 로 만든 문자 배열이 각각 `n`개의 문자(또는 바이트)를 차지한다. 추가적인 `String` 객체(`String.valueOf(arr)`)도 동일한 크기를 차지한다. 입력 크기 외에 별도의 동적 메모리는 사용하지 않는다.  

### 3. 풀이 접근법  
- **그리디**: 가장 왼쪽에 있는 `6`을 `9`로 바꾸면 전체 수가 최대가 된다.  
- **문자열 변환**: 정수를 문자열로 바꾸고 문자 배열로 변환해 직접 수정한 뒤, 다시 정수로 파싱한다.  

### 4. 잘된 점  
1. **간결함**: 로직이 10줄 이내로 매우 직관적이며, 첫 번째 `6`을 찾으면 바로 바꾸고 종료해 불필요한 연산을 최소화했다.  
2. **그리디 판단이 정확**: 문제의 특성상 가장 왼쪽 `6`을 바꾸는 것이 최적임을 정확히 구현했다.  
3. **예외 처리 불필요**: 입력이 6과 9만으로 이루어진다는 가정 하에 별도 검증 로직이 필요 없으며, 코드가 깔끔하게 유지된다.  

### 5. 개선 사항

#### 예시 – 숫자 연산 기반 구현 (O(1) 공간)

```java
class Solution {
    public int maximum69Number(int num) {
        int place = 1;          // 현재 자리값(1,10,100,...)
        int bestPlace = -1;     // 6을 바꿔야 할 가장 높은 자리

        int temp = num;
        while (temp > 0) {
            int digit = temp % 10;
            if (digit == 6) bestPlace = place; // 가장 높은 자리 저장
            temp /= 10;
            place *= 10;
        }

        if (bestPlace != -1) {
            num += 3 * bestPlace; // 6 → 9 차이는 +3
        }
        return num;
    }
}
```

- **시간**: O(log₁₀ num) (자리수만큼 반복)  
- **공간**: O(1)  

위와 같이 구현하면 메모리 할당을 없앨 수 있어 대규모 입력에서도 더 효율적이다. 그러나 현재 문자열 기반 구현도 가독성이 좋고 충분히 빠르므로, **코드 간결성을 중시한다면 그대로 유지해도 무방**하다.
