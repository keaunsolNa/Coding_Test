## Code Review

**코드 리뷰 (한국어)**  

---

### 1. 시간 복잡도  
- **O(1)**  
  - `distributeCandies` 메서드 안에서 수행되는 연산은 상수 개수의 산술 연산과 `calc` 호출뿐이며, `calc` 역시 단순히 두 번의 곱셈·뺄셈·나눗셈을 수행한다. 입력 크기 `n`·`limit`에 비례하는 반복문이나 재귀 호출이 없으므로 전체 실행 시간은 입력값에 관계없이 일정하다.

### 2. 공간 복잡도  
- **O(1)**  
  - 추가적인 배열·리스트·재귀 스택 등을 사용하지 않는다. 로컬 변수(`totalWays`, `n`, `limit`) 몇 개와 메서드 호출 스택만 사용하므로 메모리 사용량은 상수이다.

### 3. 풀이 접근법  
- **조합론 기반 포함‑배제 원리**  
  - 세 명의 아이에게 각각 `0 ~ limit` 개의 사탕을 나누는 경우의 수는 `C(n+2, 2)` (별과 막대 모델) 로 구한다.  
  - 제한을 초과하는 경우를 제외하기 위해 포함‑배제 원리를 적용한다.  
    1. 한 아이가 `limit+1`개 이상 받는 경우를 3배 빼고,  
    2. 두 아이가 동시에 `limit+1`개 이상 받는 경우를 다시 3배 더해준다.  
  - 이렇게 하면 `0 ≤ each ≤ limit` 를 만족하는 모든 분배 방법을 정확히 셀 수 있다.  

### 4. 잘된 점  
1. **수학적 식을 그대로 코드에 옮김**  
   - `calc` 메서드로 조합 `C(n,2)` 를 깔끔하게 캡슐화해 가독성을 높였다.  
2. **특수 경우 빠른 반환**  
   - `n > 3*limit` 인 경우 바로 `0`을 반환해 불필요한 연산을 방지한다.  
3. **오버플로 방지**  
   - 중간 계산을 `long` 타입으로 수행하고 최종 결과만 `int` 로 캐스팅해 32비트 정수 범위 초과 위험을 최소화했다.  

### 5. 개선 사항  
1. **입력 검증 및 주석 추가**  
   - LeetCode에서는 입력이 항상 유효하지만, 실제 프로젝트에서는 `n`·`limit`이 음수일 가능성을 대비해 검증 로직을 넣고, 각 단계가 무엇을 의미하는지 설명하는 주석을 추가하면 유지보수가 쉬워진다.  
2. **`calc` 메서드 이름 명확화**  
   - 현재는 `calc` 라는 일반적인 이름이라 의미 파악이 어렵다. `combination2` 혹은 `choose2` 와 같이 조합을 계산한다는 뜻을 드러내는 이름이 바람직하다.  
3. **경계 조건 명시**  
   - `if (n - 2 >= 2 * limit)` 조건은 `n >= 2*limit + 2` 와 동일하므로, 직접적인 수식으로 바꾸면 가독성이 향상된다.  
4. **불필요한 형변환 최소화**  
   - `1L * n * (n - 1) / 2` 에서 `1L` 은 충분히 `long` 연산을 보장하지만, `n` 과 `n-1` 을 먼저 `long` 으로 캐스팅해도 된다. 현재 형태도 문제는 없으나, 일관성을 위해 `((long)n * (n - 1)) / 2` 로 바꾸면 더 명확하다.
