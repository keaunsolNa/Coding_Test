## Code Review

**1. 시간 복잡도**  
- **O(N)** (N = 문자열 길이)  
- 한 번의 선형 스캔만 수행하고, 각 ‘?’에 대해 최대 3번의 후보 문자 검사를 하므로 상수 시간 안에 처리됩니다. 전체 루프는 문자열 길이에 비례합니다.

**2. 공간 복잡도**  
- **O(N)** (입력 문자열을 `char[]` 로 복사)  
- 추가적인 보조 배열이나 컬렉션을 사용하지 않으며, 입력을 그대로 변형하기 때문에 입력 크기와 같은 선형 메모리만 필요합니다.

**3. 풀이 접근법**  
- **그리디** 방식으로 ‘?’ 를 왼쪽·오른쪽 인접 문자와 겹치지 않는 가장 작은 알파벳(`'a'`~`'c'`)으로 교체합니다.  
- 각 위치에서 로컬하게 가능한 문자를 선택하면 전체 문자열이 조건을 만족하게 됩니다.

**4. 잘된 점**  
- **간결함**: 불필요한 조건문이나 복잡한 로직 없이 한 루프와 중첩된 3회 반복만으로 해결했습니다.  
- **정확성**: 인덱스 경계(`i > 0`, `i + 1 < arr.length`)를 명확히 체크해 배열 범위 초과 오류를 방지했습니다.  
- **문자 후보 제한**: 문제에서 제시된 `'a'`~`'c'`만 사용하도록 하여 불필요한 탐색을 최소화했습니다.  
- **읽기 쉬운 변수명**(`target`, `replacement`)으로 코드 가독성이 좋습니다.

**5. 개선 사항**  
- **공간 최적화**: 입력 문자열을 바로 `char[]` 로 변환하지 않고 `StringBuilder` 를 사용하면, 원본 문자열을 그대로 두고 결과만 생성할 수 있습니다. 다만 Java에서는 `String`이 불변이므로 현재 방식도 합리적이며, 실제 메모리 차이는 미미합니다.  
- **불필요한 변수 제거**: `target` 변수는 한 번만 사용되므로 `if (arr[i] == '?')` 로 바로 검사해도 됩니다.  
- **루프 범위 최적화**: 현재는 `for (char replacement = 'a'; replacement <= 'c'; replacement++)` 로 3번만 반복하지만, 문자 집합이 확장될 경우 `while (true)` 와 `break` 로 바꾸어 가독성을 높일 수 있습니다.  
- **예외 상황 처리**: 입력이 `null` 이거나 빈 문자열일 경우를 명시적으로 처리하면 더 견고한 구현이 됩니다. (예: `if (s == null || s.isEmpty()) return s;`)  

전반적으로 코드가 매우 깔끔하고 효율적이며, 위의 작은 개선점들을 적용하면 더욱 견고하고 가독성 높은 솔루션이 됩니다.
