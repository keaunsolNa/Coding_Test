## Code Review

**1. 시간 복잡도**  
- 현재 구현은 두 개의 중첩 루프를 사용하고 있어 **O(N²)** 시간 복잡도를 가집니다.  
- 외부 루프는 `i = 0 … N‑2`, 내부 루프는 `j = i+1 … N‑1`을 순회하므로 전체 연산 횟수는 약 `N·(N‑1)/2` 입니다.

**2. 공간 복잡도**  
- 입력 배열 외에 결과를 저장하기 위한 `ans` 배열 하나만 추가로 사용합니다.  
- 따라서 **O(N)** (결과 배열 크기)이며, 추가적인 보조 공간은 거의 사용되지 않습니다.

**3. 풀이 접근법**  
- 각 인덱스 `i`에 대해 그 뒤에 오는 원소들(`j > i`) 중 **짝수‑홀수** 혹은 **홀수‑짝수**인 경우를 직접 검사하여 카운트합니다.  
- `isEven` 플래그를 미리 계산해 내부 조건문을 간소화하는 형태의 **브루트 포스** 방식입니다.

**4. 잘된 점**  
- 코드가 직관적이고 가독성이 좋습니다.  
- `isEven` 변수를 미리 계산해 내부 `if` 문을 조금이라도 줄인 점이 효율성을 생각한 흔적입니다.  
- 불필요한 객체 생성이나 복잡한 로직 없이 순수 배열 연산만으로 문제를 해결했습니다.

**5. 개선 사항**  
1. **시간 최적화**  
   - 문제는 “각 인덱스 이후에 존재하는 짝수/홀수 개수”를 구하면 O(N)으로 해결할 수 있습니다.  
   - 뒤에서부터 순회하면서 현재까지 본 짝수와 홀수의 누적 개수를 유지하면, `i` 위치에서 필요한 카운트는 바로 `oddCount`(짝수인 경우) 혹은 `evenCount`(홀수인 경우) 로 얻을 수 있습니다.  
   - 이렇게 하면 전체 시간 복잡도를 **O(N)** 로 낮출 수 있습니다.

   ```java
   class Solution {
       public int[] countOppositeParity(int[] nums) {
           int n = nums.length;
           int[] ans = new int[n];
           int evenCnt = 0, oddCnt = 0;   // 뒤쪽에 남은 짝수·홀수 개수

           for (int i = n - 1; i >= 0; i--) {
               if (nums[i] % 2 == 0) {          // 현재가 짝수
                   ans[i] = oddCnt;            // 뒤에 있는 홀수 개수
                   evenCnt++;
               } else {                         // 현재가 홀수
                   ans[i] = evenCnt;           // 뒤에 있는 짝수 개수
                   oddCnt++;
               }
           }
           return ans;
       }
   }
   ```

2. **경계 조건**  
   - 현재 구현은 `for (int i = 0; i < len - 1; i++)` 로 마지막 인덱스를 제외하고 순회합니다.  
   - 마지막 인덱스의 결과는 항상 0이므로 별도 처리가 필요 없지만, 코드 가독성을 위해 `i < len` 로 돌리고 내부에서 `j = i+1` 조건을 그대로 두는 것이 더 일관될 수 있습니다.

3. **불필요한 연산 최소화**  
   - `nums[j] % 2` 연산을 매번 수행하기보다, 미리 `boolean[] isOdd` 같은 배열을 만들어 두면 약간의 메모리 비용을 대가로 연산을 절감할 수 있습니다. 하지만 O(N) 솔루션에서는 큰 차이가 없으니 선택 사항입니다.

**요약**  
현재 코드는 명확하지만 O(N²) 시간 복잡도로 비효율적입니다. 뒤에서부터 누적 짝/홀수 개수를 이용하면 O(N) 시간에 해결할 수 있으니, 해당 최적화 방식을 적용하는 것을 권장합니다. 코드 가독성은 유지하면서 성능을 크게 향상시킬 수 있습니다.
