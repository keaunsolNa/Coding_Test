## Code Review

**1. 시간 복잡도**  
- **O(1)**  
  입력 문자열의 길이는 항상 고정된 5(`HH:MM`)이며, `split`, `charAt`, `substring` 등 모든 연산이 상수 횟수만 수행됩니다. 따라서 입력 크기에 비례하는 반복이 없으므로 시간 복잡도는 O(1)입니다.

**2. 공간 복잡도**  
- **O(1)**  
  추가로 생성되는 문자열은 `hour`, `min`, 그리고 최종 반환 문자열 하나뿐이며, 모두 길이가 고정되어 있습니다. 따라서 사용되는 추가 메모리는 입력 크기에 비례하지 않으므로 O(1)입니다.

**3. 풀이 접근법**  
- 문자열을 `:` 로 분리한 뒤, 각 자리(`?`)를 가능한 가장 큰 숫자로 교체해 **최대 시간**을 만든다.  
- 첫 번째 자리(`hour[0]`)가 `?`이면 `1`(12시대)로, 두 번째 자리(`hour[1]`)가 `?`이면 첫 자리값에 따라 `9`(0~9시) 혹은 `1`(10~12시)으로 채운다.  
- 12시를 초과하는 경우(`hour`가 `13~19` 등)에는 `0`으로 교정한다.  
- 분(`min`)은 첫 자리 `?`를 `5`, 두 번째 자리 `?`를 `9`로 채워 00~59 범위 내에서 가장 큰 값을 만든다.  

**4. 잘된 점**  
- **문제 요구사항을 정확히 반영**: 각 자리마다 가능한 최대값을 선택해 최종적으로 가장 늦은 시간을 반환한다.  
- **불필요한 반복 없이 직접 접근**: 자리별 조건을 바로 검사하고 문자열을 재구성해 간결하게 구현했다.  
- **가독성**: 변수명을 `hour`, `min`으로 명확히 지정하고, 로직을 단계별로 나눠 이해하기 쉽다.  

**5. 개선 사항**  
1. **`split` 호출 중복 제거**  
   ```java
   String[] parts = s.split(":");
   String hour = parts[0];
   String min  = parts[1];
   ```  
   현재는 `s.split(":")`를 두 번 호출하고 있어 불필요한 문자열 배열 생성이 발생한다.

2. **`substring` 사용 최소화**  
   `substring(1, 2)` 등은 한 글자만 필요하므로 `charAt` 로 바로 읽고 `StringBuilder` 로 조합하면 더 직관적이며, 불필요한 문자열 객체 생성을 줄일 수 있다.

3. **시간 유효성 로직 간소화**  
   현재 `hour.charAt(0) == '1' && !(hour.charAt(1) == '0' || hour.charAt(1) == '1' || hour.charAt(1) == '2')` 와 같은 복잡한 조건 대신, `int h = Integer.parseInt(hour.replace('?', '0'));` 로 임시 값을 만든 뒤 `if (h > 23) hour = "00";` 와 같이 범위 검사를 하면 로직이 더 명확해진다. (하지만 문제는 12시제이므로 `if (h > 12) …` 로 조정)

4. **`StringBuilder` 활용**  
   최종 문자열을 만들 때 `hour + ":" + min` 대신 `StringBuilder sb = new StringBuilder(5); sb.append(hour).append(':').append(min); return sb.toString();` 로 작성하면 약간의 성능 향상이 있다(실제 차이는 미미하지만 일관된 스타일).

5. **예외 상황 처리**  
   입력이 항상 `HH:MM` 형식이라고 가정하지만, LeetCode에서는 보통 입력 검증이 필요 없다. 그래도 `if (s == null || s.length() != 5)` 와 같은 방어 코드를 추가하면 코드가 더 견고해진다.
