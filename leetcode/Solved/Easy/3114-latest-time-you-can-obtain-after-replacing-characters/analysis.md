## Code Review

**1. 시간 복잡도**  
- **O(1)**  
  입력 문자열의 길이는 항상 고정(5자리, “hh:mm”)이므로, 문자열을 split하고 각 자리마다 조건을 검사·대입하는 연산은 상수 횟수만 수행됩니다. 따라서 입력 크기에 비례하는 반복이 없으며 시간 복잡도는 O(1)입니다.

**2. 공간 복잡도**  
- **O(1)**  
  추가로 생성되는 문자열은 `hour`, `min`, 그리고 최종 반환 문자열 정도뿐이며, 모두 입력 길이와 동일한 상수 크기입니다. 따라서 사용되는 추가 메모리는 입력 크기에 독립적인 상수 공간입니다.

**3. 풀이 접근법**  
- 문자열을 `:` 로 split하여 시와 분을 각각 얻은 뒤, 각 자리(`?`)를 가능한 가장 큰 값으로 교체하는 **그리디** 방식입니다.  
  - 시 첫 자리: `?` → `1` (가능한 최대값을 위해)  
  - 시 두 번째 자리: 앞자리(`0` 또는 `1`)에 따라 `9` 혹은 `1` 선택  
  - 분 첫 자리: `?` → `5` (00~59 범위)  
  - 분 두 번째 자리: `?` → `9`  

**4. 잘된 점**  
- 문제의 핵심인 “가능한 가장 늦은 시간”을 간단한 조건문만으로 구현해 가독성이 좋습니다.  
- 불필요한 반복이나 복잡한 로직 없이 바로 자리별 최댓값을 정해 O(1) 시간에 해결했습니다.  
- `split(":")` 로 시·분을 명확히 구분한 점이 직관적입니다.

**5. 개선 사항**  
1. **불필요한 `split` 호출 최소화**  
   - 현재 `s.split(":")` 를 두 번 호출하고 있어 약간의 오버헤드가 있습니다. 한 번만 호출하고 결과를 재사용하면 더 깔끔합니다.  
   ```java
   String[] parts = s.split(":");
   String hour = parts[0];
   String min  = parts[1];
   ```

2. **문자열 조작 대신 `char[]` 사용**  
   - 현재 `substring` 과 문자열 결합을 여러 번 수행하고 있는데, 고정 길이이므로 `char[]` 로 변환 후 직접 수정하면 메모리 할당을 줄일 수 있습니다.  
   ```java
   char[] h = hour.toCharArray();
   if (h[0] == '?') h[0] = '1';
   if (h[1] == '?') h[1] = (h[0] == '0') ? '9' : '1';
   ```

3. **경계 조건 명시**  
   - 현재 구현은 `hour.charAt(0) == '?'` 일 때 무조건 `'1'` 로 바꾸지만, 입력이 `"??:??"` 인 경우 시 첫 자리를 `'2'` 로 할 수 없습니다(24시간 형식). 실제 정답은 `'23:59'` 이므로 현재 로직은 `hour` 가 `?` 일 때 `'2'` 로 시작하는 경우를 고려해야 합니다.  
   - 정확한 로직:  
     ```java
     if (h[0] == '?') {
         h[0] = (h[1] == '?' || h[1] <= '3') ? '2' : '1';
     }
     if (h[1] == '?') {
         h[1] = (h[0] == '2') ? '3' : '9';
     }
     ```
   - 이와 같이 시 첫 자리와 두 번째 자리의 상호 의존성을 고려하면 모든 경우에 올바른 최댓값을 얻을 수 있습니다.

4. **디버그 출력 제거**  
   - `System.out.println(hour);` 와 `System.out.println(min);` 은 테스트용이라면 괜찮지만, 실제 제출 코드에서는 제거해야 합니다. 불필요한 I/O는 성능에 영향을 주고, 채점 환경에서 오히려 WA를 초래할 수 있습니다.

5. **메서드 시그니처와 클래스 선언**
