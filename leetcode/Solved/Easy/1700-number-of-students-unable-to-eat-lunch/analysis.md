## Code Review

**1. 시간 복잡도**  
- **O(N)** (N = 학생 수 = 샌드위치 수)  
- 학생 배열을 한 번 순회해 선호도 카운트를 구하고, 샌드위치 배열을 한 번 순회하면서 남은 학생 수를 확인한다. 두 번의 선형 스캔만 수행하므로 전체 시간 복잡도는 O(N)이다.

**2. 공간 복잡도**  
- **O(1)**  
- `count` 배열은 크기가 2인 고정 배열이며, 추가적인 동적 자료구조를 사용하지 않는다. 입력 크기에 비례하는 메모리를 사용하지 않으므로 상수 공간 복잡도이다.

**3. 풀이 접근법**  
- **카운팅 기반 시뮬레이션**  
  - 학생들의 선호(0 또는 1)를 미리 카운트해 두고, 샌드위치 스택(배열)에서 차례대로 꺼내면서 해당 타입을 원하는 학생이 남아 있는지 확인한다.  
  - 현재 샌드위치 타입을 원하는 학생이 없으면, 남은 학생들은 모두 현재 샌드위치를 먹을 수 없으므로 바로 남은 학생 수(`count[other]`)를 반환한다.

**4. 잘된 점**  
- **불필요한 큐/스택 구현을 배제**하고 카운팅만으로 문제를 해결해 코드가 간결하고 효율적이다.  
- `sandwichType ^ 1`을 이용해 반대 타입을 구하는 트릭이 깔끔하게 사용되었다.  
- 입력이 0/1만 허용된다는 전제 하에 배열 크기를 최소화해 메모리 사용을 최적화했다.  

**5. 개선 사항**  
- 현재 구현은 가독성을 위해 `count` 배열을 `int[]` 대신 `int zeroCnt, int oneCnt`와 같이 명시적인 변수로 바꾸면 이해하기 쉬울 수 있다.  
- `sandwichType ^ 1` 연산은 비트 연산에 익숙하지 않은 사람에게는 다소 난해할 수 있으니, `1 - sandwichType` 같은 직관적인 표현으로 교체해도 무방하다.  
- 메서드 시그니처와 클래스 선언에 `public` 접근자를 명시했으니, LeetCode 환경에서는 `class Solution`만 있으면 충분하므로 불필요한 접근자 선언을 제거해도 된다(코드 스타일 선택 사항).
