2. **불필요한 전체 스캔 제거**  
   - 실제로는 현재 샌드위치와 일치하지 않는 학생이 연속해서 나타나는 경우, 그 학생들은 앞으로도 절대 먹지 못한다는 사실을 이용할 수 있습니다.  
   - 학생들의 선호가 0(초콜릿)과 1(치즈) 두 종류뿐이므로, 남은 학생 중 한 종류만 남았을 때 남은 샌드위치를 모두 포기하면 됩니다.  
   - 따라서 **카운트 배열**(`int[] cnt = new int[2];`) 로 학생들의 선호 개수를 미리 세고, 샌드위치를 차례대로 확인하면서 `cnt[sandwich] > 0`이면 `cnt[sandwich]--` 하고, 그렇지 않으면 루프를 종료하면 됩니다.  
   - 이 방법은 **시간 복잡도 O(n)**, **공간 복잡도 O(1)** (추가 배열 2개) 로 최적입니다.  
3. **불필요한 디버그 출력 제거**

4. **변수명 및 로직 정리**  
   - `ans` 라는 변수는 “먹지 못한 학생 수”가 아니라 “시도 횟수”처럼 보이므로 의미에 맞는 이름(`unableCount`) 으로 바꾸는 것이 좋습니다.  
   - `prevLength` 와 `afterStack` 의 비교 로직은 복잡성을 높이므로, 위의 카운트 방식으로 대체하면 불필요한 조건문을 없앨 수 있습니다.  

**예시 개선 코드 (O(n) 시간, O(1) 공간)**  

```java
class Solution {
    public int countStudents(int[] students, int[] sandwiches) {
        int[] cnt = new int[2];               // cnt[0] = 초콜릿, cnt[1] = 치즈
        for (int s : students) cnt[s]++;

        int i = 0;                            // 현재 샌드위치 인덱스
        while (i < sandwiches.length && cnt[sandwiches[i]] > 0) {
            cnt[sandwiches[i]]--;             // 해당 선호를 가진 학생이 한 명 먹음
            i++;
        }
        // i 이후의 샌드위치를 먹지 못한 학생 수가 정답
        return sandwiches.length - i;
    }
}
```
