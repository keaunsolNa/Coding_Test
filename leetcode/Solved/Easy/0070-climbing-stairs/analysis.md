## Code Review

**1. 시간 복잡도**  
- **O(n)**  
  - `for` 루프가 `n` 번 실행되며 각 반복에서 상수 시간 연산(덧셈, 변수 교체)만 수행한다. 따라서 입력 `n`에 비례하는 선형 시간 복잡도를 가진다.

**2. 공간 복잡도**  
- **O(1)**  
  - 사용되는 변수는 `previousTwo`, `previousOne`, `current`, `step` 네 개뿐이며 입력 크기에 따라 추가 메모리가 필요하지 않다. 따라서 상수 공간 복잡도를 가진다.

**3. 풀이 접근법**  
- **동적 프로그래밍(피보나치 수열) + 메모이제이션 없이 슬라이딩 윈도우**  
  - 계단을 한 번에 1칸 또는 2칸 오를 수 있으므로 `climbStairs(n) = climbStairs(n‑1) + climbStairs(n‑2)`가 된다.  
  - 전체 DP 배열을 만들지 않고, 직전 두 값만 보관하는 방식(`previousTwo`, `previousOne`)으로 메모리를 절약한다.

**4. 잘된 점**  
- **불필요한 배열 제거**: 전형적인 DP 구현에서 흔히 보이는 `int[] dp = new int[n+1]` 를 사용하지 않아 메모리 사용을 최소화했다.  
- **가독성**: 변수 이름이 의미를 잘 전달하고, 루프 구조가 직관적이라 코드 흐름을 이해하기 쉽다.  
- **경계 조건 처리**: 초기값을 `previousTwo = 0`, `previousOne = 1` 로 두고 `n` 번 반복 후 `previousOne`을 반환함으로써 `n = 0` (계단이 없을 때)도 올바르게 1을 반환한다.

**5. 개선 사항**  
- **입력 검증**: LeetCode에서는 `n`이 1 이상인 경우만 주어지지만, 함수 앞에 `if (n < 0) throw new IllegalArgumentException();` 와 같은 방어 코드를 추가하면 더 견고해진다.  
- **루프 범위 최적화**: 현재 `for (int step = 0; step < n; ++step)` 로 `n` 번 반복한다. `n`이 1일 때도 한 번 연산이 수행되는데, 이는 문제 정의상 정상이다. 다만 `n == 1`인 경우 바로 `return 1;` 로 빠져나가면 약간의 연산을 절약할 수 있다.  
- **주석 추가**: “피보나치 수열 기반 DP”와 같은 간단한 주석을 달면 코드 유지보수 시 도움이 된다.  
- **대안적 접근법**:  
  - **수학적 해법**: 닫힌 형태인 `F(n+1) = ((1+√5)/2)^{n+1} - ((1-√5)/2)^{n+1}) / √5` (Binet 공식) 를 이용해 O(log n) 시간에 빠르게 계산할 수 있다. 하지만 부동소수점 오차와 구현 복잡성을 고려하면 현재 방식이 실용적이다.  
  - **행렬 거듭제곱**: 피보나치 수열을 2×2 행렬의 거듭제곱으로 표현하면 O(log n) 시간에 구할 수 있다. 역시 구현 난이도가 높아 현재 코드가 가장 간단하고 효율적이다.  

전반적으로 코드가 깔끔하고 최적화된 형태이며, 위의 작은 개선점을 반영하면 더욱 완성도 높은 솔루션이 될 것이다.
